A security release: upgrade if you use `RetrievalGuard` access control, plugin signatures, `DevServer` or the MCP server, and re-ingest `FileVectorStore` indexes with a top-level `acl` or `requiredRole`. It fixes the four advisories listed below, and one change in access control can hide documents that were visible before.

```bash
npm install @devilsdev/rag-pipeline-utils@^3.8.1
# and, if you use the MCP server:
npx @devilsdev/rag-mcp-server@3.8.1 ./docs
```

## Security

Four advisories, fixed in this release. Each lists the affected versions and workarounds for anyone who can't upgrade yet.

- **Access control in `RetrievalGuard` and the built-in stores** (`MemoryRetriever`, `FileVectorStore`, `BM25Search`): [GHSA-8393-cmg7-9rv3](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-8393-cmg7-9rv3)
- **Plugin signature verification** (`PluginSignatureVerifier`): [GHSA-w693-22gp-m69r](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-w693-22gp-m69r)
- **The development server** (`DevServer`): [GHSA-6h47-g8cw-366q](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-6h47-g8cw-366q)
- **HTML indexing in `@devilsdev/rag-mcp-server`**: [GHSA-j2vr-gm7f-3r37](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-j2vr-gm7f-3r37)

## After upgrading

- **Re-ingest `FileVectorStore` indexes whose documents set `acl` or `requiredRole` at the top level** (not in `metadata`). Index files written by earlier versions don't contain that field, so upgrading alone doesn't restrict those documents. Documents with the restriction in `metadata`, and the in-memory stores (`MemoryRetriever`, `BM25Search`), need no action beyond upgrading.

## Changed

- **`RetrievalGuard` now requires every restriction a document sets.** A document can set `requiredRole` or `acl` at its top level, in `metadata` and on `doc`; access now requires meeting each one that is set (any one role of a list is enough for that list). This can hide documents that were visible before. If some of your documents set restrictions in more than one place, check that they set the ones you mean.

The scoped packages, `@devilsdev/rag-mcp-server` and `create-rag-pipeline` are released at 3.8.1 too. Full details: [CHANGELOG](https://github.com/DevilsDev/rag-pipeline-utils/blob/main/CHANGELOG.md) · [Blog post](https://devilsdev.github.io/rag-pipeline-utils/blog/v3-8-1-release)
