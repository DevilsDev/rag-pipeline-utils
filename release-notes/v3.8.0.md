A minor release for testing RAG in TypeScript: the answer matchers now compile with types, and a new guide shows the whole setup with Vitest. No breaking changes.

```bash
npm install @devilsdev/rag-pipeline-utils@^3.8.0
```

## Added

- **Typed matchers for TypeScript.** `@devilsdev/rag-pipeline-utils/testing` exports `RagMatchers`, the signatures of `toBeGroundedIn`, `toCite` and `toContainNoPII` on `expect`. Add them to Vitest's or Jest's `Matchers` in a declaration file and the matchers compile, with a wrong argument reported as a type error. Until now `expect(result).toBeGroundedIn()` didn't compile in TypeScript, and the declaration the Testing page suggested failed under Vitest 5. [Matchers in TypeScript](https://devilsdev.github.io/rag-pipeline-utils/docs/Testing#matchers-in-typescript)

  ```ts
  import "vitest";
  import type { RagMatchers } from "@devilsdev/rag-pipeline-utils/testing";

  declare module "vitest" {
    interface Matchers<R, T> extends RagMatchers<R> {}
  }
  ```

- **A "Testing RAG in TypeScript" guide**: typed matchers on an offline test pipeline, catching a wrong number with `checkAnswer`, and a test set scored by `rag-pipeline eval` in CI. It is built from a runnable project, [examples/testing-typescript](https://github.com/DevilsDev/rag-pipeline-utils/tree/main/examples/testing-typescript), which is type-checked, tested and evaluated with the latest Vitest and TypeScript before each release. [The guide](https://devilsdev.github.io/rag-pipeline-utils/docs/Testing-RAG-TypeScript)
