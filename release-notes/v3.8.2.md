A security release: upgrade if you use the vector-store retrievers (`QdrantRetriever`, `PineconeRetriever`, `WeaviateRetriever`, `PgVectorRetriever`), `HybridRetriever`, `GuardrailsPipeline`, plugins from `.ragrc.json` or `hub install`, `AuditLogger`, `DevServer` or the MCP server, and re-ingest vector-store documents with a top-level `acl` or `requiredRole`. It fixes the five advisories listed below, and some changes in access control can hide documents that were visible before.

```bash
npm install @devilsdev/rag-pipeline-utils@^3.8.2
# and, if you use the MCP server:
npx @devilsdev/rag-mcp-server@3.8.2 ./docs
```

If you install `@devilsdev/rag-core`, `rag-guardrails`, `rag-connectors` or `rag-eval` directly, upgrade them to 3.8.2 as well.

## Security

Five advisories, fixed in this release. Each lists the affected versions and workarounds for anyone who can't upgrade yet.

- **Access control in the vector-store retrievers and `HybridRetriever`** (`QdrantRetriever`, `PineconeRetriever`, `WeaviateRetriever`, `PgVectorRetriever`): [GHSA-234f-v76m-p9wc](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-234f-v76m-p9wc)
- **Streamed and blocked answers in `GuardrailsPipeline`**: [GHSA-whr9-r3mv-2565](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-whr9-r3mv-2565)
- **Plugin signature verification and install checks** (plugins from `.ragrc.json`, `hub install`): [GHSA-m9gh-5x7v-rqj2](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-m9gh-5x7v-rqj2)
- **Denial of service in text checks, plugin archive extraction and `@devilsdev/rag-mcp-server`, and the `DevServer` Host check**: [GHSA-4jh4-qv86-j2gw](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-4jh4-qv86-j2gw)
- **Integrity and tenant filters in `AuditLogger`**: [GHSA-89fq-598q-39wc](https://github.com/DevilsDev/rag-pipeline-utils/security/advisories/GHSA-89fq-598q-39wc)

## After upgrading

- **Re-ingest documents with a top-level `acl` or `requiredRole` stored by `QdrantRetriever`, `PineconeRetriever`, `WeaviateRetriever` or `PgVectorRetriever`.** These stores now keep a document's top-level restrictions; documents stored by earlier versions were saved without them, so upgrading alone doesn't restrict those documents. [Do I need to re-ingest?](https://devilsdev.github.io/rag-pipeline-utils/docs/Security#do-i-need-to-re-ingest) explains how to check a store.
- If you're upgrading from 3.8.0 or earlier, also re-ingest `FileVectorStore` indexes whose documents set `acl` or `requiredRole` at the top level (fixed in 3.8.1).

## Changed

Some of these change behaviour:

- **`HybridRetriever` keeps the restrictions of every copy of a document**, which can hide documents that were visible before. The role `rag:no-access` is reserved.
- **`GuardrailsPipeline`** returns blocked results without text, buffers streamed answers when a post-generation guard is set, and withholds results the retrieval guard couldn't check.
- **Plugins configured in `.ragrc.json` are verified before they load**, and unsigned plugins warn.
- **`hub install` scans more and passes less**; `hub certify` scans the entry file the same way.
- **`@devilsdev/rag-mcp-server` limits tool inputs and check time**; each limit can be raised with a CLI flag or environment variable (see the package README).
- **`DevServer` checks the `Host` header of loopback requests** whatever it is bound to.
- **`AuditLogger` chains and verifies its records**, stores a signing key when none is configured, and validates tenant filters.

The scoped packages, `@devilsdev/rag-mcp-server` and `create-rag-pipeline` are released at 3.8.2 too. Full details: [CHANGELOG](https://github.com/DevilsDev/rag-pipeline-utils/blob/main/CHANGELOG.md) · [Blog post](https://devilsdev.github.io/rag-pipeline-utils/blog/v3-8-2-release)
