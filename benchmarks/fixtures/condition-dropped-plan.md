# Condition-dropped benchmark (pre-registered)

Committed before any case is generated or any number is produced. Every
number these runs produce goes on the Benchmarks page (block
`bench:condition-dropped`, rendered by `benchmarks/render.js`), whatever it
shows. Models: `claude-sonnet-5-5` generates the cases;
`claude-haiku-5-5` and `claude-sonnet-5-5` are the judges. No other model.
Spend for this benchmark stops at US$8 (`--cap` = the all-time total before
it + 8, through `benchmarks/claude-cache.js`).

## What is measured

`checkConditionConsistency` (3.9, the "condition left out" check) on claims
that leave out a restricting clause of their source, and on controls that
must stay supported. The positive class is **unsupported** (the claim drops
a restriction). Precision = flagged positives / all flagged; recall =
flagged positives / all positives.

## Cases

- 350 source/claim pairs, generated by `claude-sonnet-5-5` in batches of 25
  (temperature 0, each batch's prompt fixed in
  `benchmarks/condition-dropped.js`), from realistic text in four domains,
  in equal shares: workplace policy, contracts, medical guidance, product
  terms.
- **175 positives**, 25 for each of seven groups. Six restricting-marker groups: approval
  ("with ... approval/permission/consent/sign-off"); condition ("only if",
  "only when", "if"); "unless"; proviso ("provided (that)", "subject to",
  "as long as"); waiting period ("after <number> <unit>"); eligibility or
  exception ("for <people> who/with ...", "except"). Each claim keeps the
  source's main statement and drops the restriction, in the source's words
  or a light rewording. The seventh group, **near miss** (added before
  generation, at the maintainer's request): the restriction is dropped, but
  the answer still contains one of its words in another sentence that is
  itself grounded in a second source ("Your manager sets the team schedule
  each week. Remote work is allowed two days per week.", with the schedule
  sentence as a second source). It includes coordinators inside the clause
  ("with manager and HR approval") and bare "when" conditions, which the
  3.9 rule does not list as a marker.
- **175 controls**, labelled supported: 75 faithful paraphrases that keep
  the condition (in other words, or in a second sentence of the answer); 75
  claims that drop a contrasting clause ("but not", "whereas", "while",
  "however") of a source that has one; and 25 **non-restricting if/except**
  (added before generation): sources whose "if" or "except" does not
  restrict the claim ("even if", "if any", "if applicable", "whether or
  not"), and a sub-label `except-as-required-by-law` for "except as required
  by law", reported on its own so the maintainer can decide on it.
- Split confirmed by the maintainer: six marker groups × 25 positives and
  150 controls, then the near-miss group and the non-restricting control
  group added, 350 in total.
- `src/` is not changed for the near-miss or non-restricting groups unless
  the dev split shows the pattern (see Split).
- Each case records its generator label, marker group, domain and control
  type. All cases are written to
  `benchmarks/fixtures/condition-dropped-cases.jsonl` with
  `"review": "needs human review"`: the labels are the generator's, not a
  person's, until reviewed.

## Split

- Seed 20261108: a seeded shuffle within each (marker group or control type)
  stratum, first half dev, second half test. The split is written into the
  cases file.
- **Only dev cases may inform changes to the rule.** Any change to `src/`
  made after this plan is committed is listed in the results with the dev
  cases that motivated it. Test-split numbers are reported once, after the
  code is frozen, and are not used to change it.

## Runs (test split, and dev for reference)

1. Lexical, **before**: the 3.8.0 code (`v3.8.0` tag, in a separate
   worktree), `checkAnswer` with no judge.
2. Lexical, **after**: this branch, `checkAnswer` with no judge.
3. Judge, after: `checkAnswer({ judge })` with `claude-haiku-5-5`, then with
   `claude-sonnet-5-5` (temperature 0, cached). The judge only sees
   `low_overlap` sentences, so most cases make no call.
4. Judge, before: the same two judges on the 3.8.0 code.

Reported per run: precision, recall, F1, false alarms on each control type,
and recall per marker group, with counts. Disagreements between the before
and after lexical runs are listed case by case (dev and test).

## Cost estimate

- Generation: 14 Sonnet batches × about 1.5k input and 5k output tokens ≈
  14 × $0.053 ≈ **$0.74**.
- Judges: at most 350 calls per judge per code version (in practice only
  `low_overlap` sentences), about 0.8k input and 0.15k output tokens each:
  Haiku 5.5 ≈ 350 × $0.00016 ≈ $0.06; Sonnet 5.5 ≈ 350 × $0.0031 ≈ $1.09;
  two code versions ≈ **$2.30** at most.
- Total ≈ **$3.04** at most, against the $8 allocation.

## Human review pass (added for 3.9, after the runs)

A read of the 75 `contrast-dropped` cases labelled supported, after the
benchmark ran; the cases file is unchanged. Two likely leave out a
restriction of the main statement and so may be mislabelled:
`cd-contrast-dropped-10-25` (test; "but not alcohol") and
`cd-contrast-dropped-10-24` (dev; "but not with more than one gaming
console"). Three are borderline exceptions for a subgroup:
`cd-contrast-dropped-10-03` (test), `cd-contrast-dropped-10-11` (test) and
`cd-contrast-dropped-10-16` (dev). The human review pass should check these
five first.
